# Open Site Health · 公益站点健康监控

**开源 · 非商业 · 面向公众的公益基础设施**

帮助小型公益组织、开源项目与志愿站点维护者，低成本掌握「站点是否可用、证书是否即将过期」，并在异常时及时收到告警。

---

## 解决什么问题

许多公益站点、志愿项目官网、开源文档站由少数志愿者维护，往往缺少专职运维。站点宕机、HTTPS 证书过期后，捐赠入口、报名页或文档会静默失效，受众与捐赠方却难以及时发现。

本项目提供一条最短路径：

1. **登记 URL**（站点地址）
2. **定时探测**可用性与证书过期时间
3. **告警通知**（邮件 / Webhook）

让没有运维团队的公益与开源维护者也能持续盯住关键入口。

## 目标受众

- 小型公益组织 / NGO 的站点维护者
- 开源项目文档站与官网维护者
- 志愿活动报名页、信息公开页的负责人

## 为什么重要

- **保护公众入口**：捐赠、报名、信息公开依赖站点持续可用
- **降低运维门槛**：无需自建复杂监控栈，一条路径即可跑通
- **开源可复用**：任何人可自托管，长期改进，不绑定商业付费墙

## 非商业声明

本项目为 **开源公益工具**，不收费、不售卖托管服务、不以本软件盈利。仓库公开，欢迎 fork 与自托管。

## 为什么需要服务器

探测与告警必须 **7×24 在线调度**，无法只靠用户本机浏览器完成：

| 能力 | 说明 |
|------|------|
| 定时探测 | 按间隔对已登记 URL 发起 HTTP(S) 检查 |
| 证书检查 | 读取 TLS 证书过期时间并预警 |
| 告警投递 | 失败或临近过期时发送邮件 / Webhook |
| 状态持久化 | 保存目标列表、最近探测结果与告警记录 |

### 建议运行环境（起步规格）

| 项 | 建议 |
|----|------|
| **OS** | Linux（推荐 Ubuntu 22.04+ / Debian 12+） |
| **CPU** | 1 vCPU（百级目标以内足够） |
| **内存** | 512 MB–1 GB |
| **磁盘** | 10 GB（系统 + 日志 + 轻量数据库） |
| **网络** | 可出站访问被监控站点；若用邮件/Webhook 需可访问对应服务 |

### 预期负载（初期）

- **目标规模**：约 50–200 个监控 URL
- **探测频率**：每 5 分钟一轮（可配置）
- **并发**：单机低并发探测即可（默认串行或小并发）
- **存储**：元数据与近期结果，日增量通常为 MB 级

负载随「目标数 × 探测频率」线性增长；超出建议规模时可水平扩展 worker 或提高规格。
